# VM 验收清单（尚未执行）

准备干净 Rocky VM，记录主/次版本、CPU 架构、网络和磁盘空间；先创建 VM 快照。

1. 校验发布 SHA256，运行 `doctor`、`--help`，确认权限和架构输出。
2. 普通用户运行 `env install python --dry-run`，检查不创建 `/var/lib/rockdev`、不修改 repo 文件和 RPM 清单。
3. 对每个候选镜像运行 `mirror check <名称>`；确认元数据匹配目标系统。
4. 实际切源，保存备份 ID；运行 `dnf repolist`、查询包，恢复备份并比较原 repo 摘要。
5. 再切同镜像，确认不产生新备份。编辑 repo 后恢复应拒绝覆盖。
6. 模拟刷新时断网，确认错误包含恢复状态；重新联网后刷新 DNF。强制终止场景验证备份可手动恢复。
7. 分别安装 python/java/go/node/build。Python 创建 venv 并运行脚本，Java 编译运行 Hello.java，Go 编译运行 main.go，Node 执行脚本并安装一个公开包；记录所有版本。重复安装不应破坏可用环境。
8. 创建 python3 和 nodejs（模块包）按需仓库；检查所有 RPM 签名和 repodata，复制到相同系统的干净 VM，导入发行版官方可信公钥，只启用该本地仓库，断网安装并运行示例。确认不会访问远程仓库。
9. 模拟下载断网/磁盘不足/缺失签名；确认不发布目标目录，已有目录不覆盖。
10. 并发启动两个修改任务，确认第二个被锁阻止；终止第一个后锁应释放。检查日志 SUCCESS/FAILED 与真实状态一致。

仅在对应 VM 项通过后，才能将该系统/架构标为已验证。未通过的包名、模块流和仓库布局继续调整，不用 Windows 单元测试结果替代。
